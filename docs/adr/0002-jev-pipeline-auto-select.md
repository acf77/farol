# Jev may auto-select only pipelines that opt in

Farol asks Jev which non-mandatory pipelines to add after a code-changing Chat turn. That decision is probabilistic and soft-fail: a low or mid-range score adds nothing. Some catalog pipelines are not pure validators — they mutate version files, build distributables, or otherwise perform release work — so a hesitant “maybe” must never be enough to run them.

We decided that a pipeline is eligible for Jev auto-selection only when it sets `autoSelectable: true` (the Pipeline editor checkbox **Allow Chat to auto-select**). The flag defaults to off, persists beside `mandatory`, and is ignored for mandatory pipelines (those always run on file-changing turns). Selection is one **Choice** over the opted-in candidates plus a host-prepared `none` escape hatch: the winning id applies only when it is in that prepared set and its probability clears `JEV_SELECTION_THRESHOLD`; below the bar, an unknown id, or `none` means do not add. Questions carry a compact bounded description of each candidate’s steps, and the decision state includes changed targets plus already-selected and mandatory coverage so redundancy can be judged. Logs record the Choice outcome (`selected` / `none` / `not-selected` / `low-confidence` / `unknown-id`) and a size summary of the state, never the state text itself.

We rejected lowering the threshold from the observed 0.24–0.32 cluster (no labeled false negatives), asking Jev about every non-mandatory pipeline by default, treating below-threshold selection scores as tri-state “inconclusive” the way step verdicts do, and asking one independent boolean per candidate (N absolute questions are not equivalent to a relative Choice and can over-add).
