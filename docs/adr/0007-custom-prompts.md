# Custom prompts are added by Farol each turn, not typed into the message

Users want standing instructions ("answer briefly", "run vitest, not jest") that apply to every chat without pasting them each time, and that they can switch on and off. We decided the main process adds every switched-on **Custom prompt** to the agent's prompt on each attempt, inside one `<custom_instructions>` block placed after the task and before Farol's own instructions. It is re-read every attempt and never written into the chat history, so toggling applies from the next turn and resumed sessions do not accumulate stale copies. Farol's marker rules stay last, so a prompt cannot quietly override them, and `custom_instructions` tags inside a prompt are escaped so it cannot close the block early.

There are two scopes. **Global prompts** live in application data with their own on/off flag. **Project prompts** live in `.farol/prompts.json` on the primary checkout (shared by linked worktrees, like pipelines) so a team can commit them, but whether each is on is saved per machine and never in that file. A repo you clone therefore cannot switch its own instructions on; its prompts start off until you turn them on.

Considered and rejected: prepending the text to the user's message (pollutes the transcript and the resumed session with a copy per turn); a slash-command picker that inserts the text (users asked for on/off standing instructions, not one-shot inserts); template variables (plain text for now); putting global prompts in `settings.json` (other sections save the whole settings object and could overwrite prompt edits); storing project on/off state in the repo file (a cloned repo could steer your agent).
