# Context meter from the CLI's own token counts; Fresh start instead of clearing

With resumed CLI sessions (ADR 0005) the conversation lives inside the CLI, so Farol's prompt size says nothing about how full the agent's context is. We decided the reading comes from the tokens each CLI reports for its latest model call — Claude's per-message `usage` (subagent messages skipped), OpenCode's per-step `tokens`, OMP's per-message `usage` — against the model's window when known (Claude Code reports it; otherwise a small table that only names Claude windows). Codex reports turn totals that add up every call in the turn and Cursor reports none, so both show no reading rather than a wrong one. The composer shows `ctx 62%` (or a token count without a known window), amber from 70% of the window or 150k tokens, and the chat suggests a **Fresh start** at that level or when the agent stops on its context limit.

A **Fresh start** keeps the chat. While the old session is still resumable, the agent writes a handoff note from everything it holds in one read-only (Plan mode) turn; Farol then drops the session and keeps only the task, the latest two requests and that note, so the next message starts a new session from them. If the agent writes no note, nothing changes.

Considered and rejected: estimating tokens from characters (wrong once the history lives in the CLI); a percentage from guessed windows for models Farol cannot name; recommending Clear (loses the transcript and everything the agent learned); a Farol-side summarizer call (the agent that did the work writes the note, and only when asked); starting fresh automatically (the user decides when losing detail is worth it).
