# The todo list is checked at the start and at the end of each message

An agent kept the checkout's todo list only when it chose to send a `FAROL_TODOS:` line, so old items stayed `in_progress` with no sign of which chat owned them. We decided each user message checks the list twice. The prompt asks for a line at the start of the reply, which Farol saves as soon as it is complete, and for a line just before the final marker. Farol enforces only the end: once the run is complete (validation passed, none was needed, or a plan is finished), it starts one closing turn when the list is not empty and either the agent's last turn did not end with a saved line (none, a failed save, or tool calls after it) or an item of this chat is still `in_progress`. The closing turn comes after validation so the agent knows the result, changes no files, and leaves the run with its completion message. Each item also records the chat that added it and when it last changed; Farol stamps both when it saves the agent's list, and the agent removes finished items from earlier requests when it starts.

Considered and rejected: a prompt rule alone (a model that ignores it leaves the list stale); a closing turn before validation (the agent cannot know the result yet, so the item for the fix stays `in_progress`); more than one closing turn per message (a model that ignores the request would loop); Farol deleting old finished items by itself (it cannot tell which are still wanted); a source field written by the agent (it would drift or be wrong — Farol matches items by text and stamps them).
