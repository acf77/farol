# Jev selects optional tool capabilities before each managed Chat turn

Managed Chat used to launch every coding CLI with its full default tool set. Jev already scored post-turn pipeline selection and step verdicts; it did not sit on the tool path. Narrowing tools per turn is the higher-leverage use of an evaluation model: less wandering, fewer irrelevant tools, and clearer policy — but only if uncertain scores never strand a coding turn.

We decided that before each Build-mode agent invocation Farol asks Jev one boolean per optional capability family (`edit`, `shell`, `web`). Inspection tools always stay available. A family is omitted only when Jev is confidently sure the turn can finish without it (`decide` at `JEV_TOOL_CONFIDENCE`); mid-band answers, missing answers, timeouts, and missing keys fail open to the full tool set. Claude and OMP receive a native `--tools` allowlist; Codex, Cursor, OpenCode, and OpenRouter keep their argv unchanged and receive the same capability policy as a mandatory prompt clause (including read-only shell inspection when that is how the provider reads files). Plan mode keeps its existing review gates and never asks Jev for tools. Pipeline auto-selection remains a separate, permanent post-turn responsibility. Prompt-policy violations observed in tool cards are logged for diagnosis only in v1 — Farol does not kill the process mid-tool.

We rejected advisory-only injection (no real narrowing), shadow-then-enforce as the initial rollout (the product decision was immediate enforcement), failing closed when a provider lacks a per-run allowlist, removing pipeline auto-selection while building tool selection, and auto-killing runs on the first omitted-family tool card.
